# v0.2.0 official live-schema comparison

Source: the captured `output/official-tools.json` (47 public tools) and `output/official-call-trace.jsonl`. This is a design comparison only: no Adobe binary code, Beta runtime, forwarding, or Adobe MCP QA is used by this project.

The captured 50-text task used `ListDocuments → GetCanvasStructure → GetObjectStructure ×2 → SetAppearance(50 UUIDs) → GetVisualAppearance(50 UUIDs)`. The two mutation calls were batch calls; the measured server durations were 32.7 ms and 10.1 ms. v0.2.0 adopts the relevant public semantics—minimum reads, one batch write, and at most one batch visual check—without copying implementation.

## Canonical Core routing patterns

- All text → red: `find_objects({ object_types: ["text"], set_properties: { fill: { type: "rgb", r: 255, g: 0, b: 0 } } })`; only if the user asks to verify, one `get_visual_appearance` batch follows.
- Known UUIDs → shared red: one `set_appearance({ uuids, fill })`; optionally one visual batch verification.
- Selected artwork → right 20pt: one `get_selection`, then one `move_objects({ uuids, x: 20 })`.
- Document-wide font replacement: use its task-level donor capability rather than iterating text frames.
- MASTER protection / work copy: only after explicit user opt-in, `create_work_copy → Core operations → dpm_save_work_copy`.
